STEP 3: CONTEXT ASSEMBLY & SELECTION IMPLEMENTATION
================================================================================

□ ContextAssemblyService (Main Service)
  ✓ Location: app/context_assembly/context_assembler.py
  ✓ Public API:
    - __init__(self, db: Session)
    - assemble(tenant_id, workspace_id, query, retrieved_rule_ids, hybrid_results, token_budget, retrieval_model, retrieval_top_k, rrf_k_constant) → AssembledContext

□ Step 1: Validate Ownership & Fetch
  ✓ Method: _validate_and_fetch_rules()
  ✓ Query: WorkflowBusinessRule → WorkflowKnowledge filtered by workspace_id
  ✓ Deduplicates by rule ID (dict keyed by id)
  ✓ Rejects cross-workspace rules (logs warnings)
  ✓ Returns: Dict[rule_id → WorkflowBusinessRule]

□ Step 2: Build Provenance Chains
  ✓ Method: _validate_provenance_chain()
  ✓ Walks full chain: Rule → Knowledge → Document → Workspace
  ✓ Validates workspace_id ownership at each step
  ✓ Marks is_complete = True if full chain exists
  ✓ Never fabricates missing data
  ✓ Logs missing links to missing_links array
  ✓ Returns: SourceProvenance object

□ Step 3: Apply Token Budget
  ✓ Method: _apply_token_budget()
  ✓ Algorithm:
    1. Order by RRF score (from retrieval)
    2. For each rule: estimate_tokens(rule.rule_text)
    3. If rule_tokens > token_budget: exclude with "RULE_TEXT_TOO_LARGE"
    4. Elif total_tokens + rule_tokens <= token_budget: include
    5. Else: exclude with "BUDGET_EXHAUSTED"
  ✓ No truncation of individual rules
  ✓ Deterministic ordering (reproducible)
  ✓ Returns: (selected_rules, excluded_rules)

□ Step 4: Detect Conflicts
  ✓ Method: _detect_conflicts()
  ✓ Heuristic: same condition + outcome + different threshold → conflict
  ✓ Marks both rules with conflict metadata
  ✓ Preserves both in selected_rules (no auto-resolution)
  ✓ Records conflict pairs: list[tuple(rule_a_id, rule_b_id)]
  ✓ Returns: list[tuple]

□ Step 5: Calculate Quality Metrics
  ✓ Token accounting:
    - estimated_tokens_used = sum(rule.estimated_tokens for rule in selected)
    - estimated_tokens_remaining = max(0, token_budget - used)
  ✓ Provenance completeness:
    - incomplete_count = len([r for r in selected if not r.provenance.is_complete])
    - completeness_pct = (total - incomplete_count) / total * 100
  ✓ Conflict summary:
    - has_conflicts = len(conflicting_rule_pairs) > 0

□ Logging Implementation
  ✓ context_assembly_start (INFO) — Initial parameters
  ✓ context_assembly_empty_retrieval (INFO) — No rules retrieved
  ✓ context_assembly_no_validated_rules (WARNING) — All rules rejected
  ✓ context_assembly_rejected_rules (WARNING) — Workspace mismatch
  ✓ context_assembly_workspace_mismatch (ERROR) — Ownership violation
  ✓ context_assembly_complete (INFO) — Final statistics

STEP 4: CONFLICTING RULES HANDLING
================================================================================

□ Conflict Detection & Preservation
  ✓ Policy: Do NOT auto-resolve conflicts
  ✓ Behavior:
    1. Detect conflicts using heuristic (same condition + outcome, different threshold)
    2. Mark both rules: conflicts_with_rule_ids, conflict_reason
    3. Include both in selected_rules (NOT filtered out)
    4. Record pairs: AssembledContext.conflicting_rule_pairs
    5. Set flag: AssembledContext.has_conflicts = True
  ✓ Metadata preserved:
    - Each rule retains source document, version, page number
    - Conflict pairs explicitly listed
    - Caller can implement own resolution
  ✓ Never modifies rules or rankings

  ✓ Reject: Rules from other workspaces with logging
  ✓ Implicit: Tenant boundary via workspace_id
  ✓ Denormalized tenant_id on BRDDocument for efficiency

□ Missing Link Handling
  ✓ If link missing:
    1. Mark in missing_links array
    2. Set is_complete = False
    3. Keep field NULL (no fabrication)
    4. Preserve rule (still included)
    5. Log for audit trail
  ✓ Examples:
    - Rule created before DocumentVersion model: document_version_id = NULL
    - Rule migrated from external system: brd_document_id = NULL
    - Version deleted: document_version_id invalid
